# 프레임 생성 계획

블록 매칭 생성기, 학습 1, 2단계, RIFE 생성기를 구현했습니다. 학습 3단계(신경망 미세 조정)는 아직 없습니다. 실제 게임에서는 아직 확인하지 못했습니다.

## 사용자 요구

- 이 PC의 성능은 신경 쓰지 않는다. 테스트는 다른 기기에서 한다.
- 텀프로젝트이므로 한계가 있더라도 비교적 새로운 방식을 시도한다.
- 연결한 게임을 기록하고, 게임별 특징에 맞춰 프레임 생성 방식을 다르게 하며, 쓸수록 좋아지게 한다.
- 예: 리듬게임은 노트가 나오는 영역을 집중해서 부드럽게 만든다.

## 결정 사항

- 구현 범위: 옵션 B. 블록 매칭과 학습 1, 2단계를 먼저 완성한 뒤 RIFE 기반 생성기를 추가한다. 게임별 미세 조정은 일정이 남으면 진행한다.
- 테스트 기기 GPU: 아직 모른다. GPU 제조사에 묶이지 않게 만들고, 부담은 품질 설정으로 조절한다.
- 기본값: 배수는 주사율까지 자동, 방식은 보간, 움직임 격자는 1/4 해상도. 사용자가 따로 정하지 않아 제안값을 그대로 썼고 모두 설정에서 바꿀 수 있다.

## 구현한 파이프라인

`src/framegen.cpp`, `src/framegen_shaders.h` (D3D11 컴퓨트 셰이더)

진짜 프레임이 올 때:

1. 앞 프레임과 비교해 내용이 같으면 버린다. 캡처는 게임이 그리지 않아도 프레임을 보내기 때문이다 (30fps 창에서 초당 60번 온 것을 확인했다).
2. 휘도 피라미드를 만든다 (원본, 1/2, 1/4, 1/8, 1/16).
3. 두 방향(A->B, B->A)으로 블록 매칭을 한다. 1/16에서 전체 탐색하고, 후보(굵은 단계, 이전 프레임, 화면 지도)와 주변 탐색으로 세밀하게 내려간다. 그 자리에서 두 프레임이 같은 칸은 탐색 없이 움직임 0으로 둔다.
4. 후보가 모두 맞지 않는 칸은 1/8 영상에서 넓게 찾는다 (작고 빠른 물체용).
5. 양방향 결과가 서로 반대인지 검사해 신뢰도를 구한다.

화면을 그릴 때마다:

1. 표시 시계로 A와 B 사이의 시점 t를 구한다. 캡처 시각의 흔들림을 바로 따라가지 않도록 천천히 맞춘다.
2. 블록을 시점 t의 위치로 옮겨 적고(투영), 빈칸은 움직임이 작은 주변 벡터로 채운다. 벡터를 그대로 쓰지 않고 옮겨 적어야 작은 물체가 배경의 움직임에 묻히지 않는다.
3. 픽셀마다 주변 칸의 벡터와 "움직임 없음"을 후보로 놓고 두 프레임이 잘 맞는 후보에 비중을 준다. 한쪽에만 보이는 곳은 그쪽 색을 쓰고, 맞는 후보가 없으면 블렌딩한다.
4. 결과를 기존 업스케일에 넘긴다. 커서는 보간하지 않으므로 최신 위치로 그려진다.

게임이 주사율만큼 프레임을 내면 넣을 자리가 없으므로 그대로 보여 주고 지연도 늘리지 않는다.

## 게임별 학습

`src/game_profile.cpp`. 실행 파일 이름으로 게임을 구분하고 `profiles/게임이름.json`에 저장한다. 게임 화면은 저장하지 않는다.

| 단계 | 상태 | 내용 |
|---|---|---|
| 1. 설정 자동 조정 | 완료 | 1초마다 F0, F1, F2 중 F1을 가리고 현재 값과 후보 값으로 만들어 실제 F1과 비교한다. 6번 평균으로 후보가 더 좋으면 바꾼다. 대상: 칸 크기, 탐색 범위, 벌점, 허용치, 화면 지도 사용 여부 |
| 2. 화면 지도 | 완료 | 화면을 32x18칸으로 나눠 칸별 주된 움직임, 움직이는 비율, 고정 비율을 쌓는다. 움직임 후보로 쓰고, 일반/리듬게임/스크롤 유형을 판단한다 |
| 3. 신경망 미세 조정 | 미착수 | RIFE 생성기와 일정이 먼저 필요하다 |

화면 지도는 강제로 쓰면 점수가 떨어지는 장면이 있었다 (pan_ui). 그래서 채점에서 더 좋을 때만 켜지는 값으로 만들었다.

### RIFE와 블록 매칭 비교

이웃한 두 프레임의 한가운데(t=0.5)와 1/4 지점(t=0.25). 입력 높이는 품질별로 빠름 256, 기본 384, 고품질 576이다.

1280x720, RIFE 기본 품질:

| 장면 | 블록 t=0.5 | RIFE t=0.5 | 블록 t=0.25 | RIFE t=0.25 |
|---|---|---|---|---|
| pan | 50.76 | 54.09 | 52.06 | 54.18 |
| pan_ui | 48.40 | 46.06 | 49.70 | 47.38 |
| sprites | 50.91 | 53.38 | 50.36 | 50.41 |
| rhythm | 22.64 | 28.06 | 24.16 | 28.01 |
| fast_pan | 38.98 | 52.96 | 40.89 | 53.15 |
| fade | 46.87 | 49.81 | 48.46 | 51.42 |

- RIFE는 작고 빠른 노트(+5.4dB)와 빠른 이동(+14dB)에서 크게 낫고, 밝기 변화에서도 블록 매칭의 약점이 없다.
- 고정 UI 장면은 RIFE가 낮다. 입력이 낮을수록 심해서 빠름 품질은 42.05dB, 고품질은 48.98dB이다. 합성에 "움직임 없음" 후보가 없고 움직임을 작은 해상도에서 가져오기 때문으로 본다.
- 신경망 시간(GTX 1060): 자체 테스트에서 입력 높이 256은 24~28ms, 384는 40~50ms, 576은 69~74ms. 실행 중에는 GPU가 계속 일해 384가 21~25ms로 더 짧았다.

RIFE 실행에서 합성의 82%가 RIFE였고 나머지는 결과가 늦어 블록 매칭으로 대신했다. 같은 설정의 다른 실행에서는 85~100%였다.

## 측정으로 확인한 한계

- rhythm 장면은 블렌딩보다 낫지만 22dB대로 낮다. 생김새가 같은 노트가 여럿이면 다른 노트와 짝지어 일부가 깨진다.
- fade 장면은 블렌딩보다 낮다. 밝기 변화를 움직임으로 착각하는 경우가 남아 있다. 학습으로 많이 줄지만 없어지지는 않는다. 평균 밝기 차이를 빼는 방법을 시도했으나 매끄러운 무늬에서 오히려 크게 나빠져 되돌렸다.
- 점수는 계산으로 만든 영상의 값이다. 게임에서의 품질과 체감은 아직 확인하지 못했다.
- 학습은 채점 때마다 움직임 추정을 2번 더 하므로 1초에 한 번 GPU 부담이 늘어난다.
- 학습은 블록 매칭의 값만 조정한다. RIFE를 쓰는 동안에도 채점은 돌지만 RIFE 자체는 좋아지지 않는다.
- RIFE는 지연이 신경망 시간만큼 더 늘어난다 (위 표에서 52ms -> 76ms). 프레임 간격의 70%를 넘으면 입력 해상도를 자동으로 낮추고, 낮춘 값은 그 실행 동안 유지한다.
- RIFE는 시점 0.5의 움직임 하나를 비례해서 다른 시점에 쓴다. 근사라서 t=0.25에서 sprites 점수가 내려간다 (53.38 -> 50.41).
- 입력 크기가 바뀔 때마다 신경망 세션을 다시 만들어 몇 초 동안 블록 매칭을 쓴다.

## 사용자에게 이미 설명한 한계

- 보간은 입력 지연을 늘린다. 30fps 게임이면 약 33ms + 계산 시간(추정치)이고, 학습으로 줄어들지 않는다.
- 게임 프레임이 모니터 주사율 이상이면 넣을 자리가 없다. 60Hz 모니터에서는 60fps 미만일 때만 효과가 있다.
- 게임의 움직임 정보 없이 화면만 보므로 가장자리, UI 주변, 빠른 움직임에서 깨짐이 생긴다.
- 오차 점수와 체감은 다르다. F0과 F2는 실제 보간보다 간격이 2배 넓어 근사치다.
- 1, 2단계의 향상에는 끝이 있다. 계속 좋아지는 효과는 3단계가 필요하다.
- 3단계는 게임 화면을 디스크에 저장한다. 용량 제한과 삭제 기능을 넣고 외부로 전송하지 않는다.
- 개발 계획의 마지막이 12월이라 일정이 빠듯하다.

## 설정 창과 단축키

"프레임 생성" 구역: 프레임 보간(Alt+Shift+F), 배수, 품질, 방식(보간/외삽 실험), 생성기(블록 매칭/RIFE), 게임 유형, 움직임 시각화, 상태(진짜 fps, 계산 시간).
"게임별 학습" 구역: 켜기/끄기, 게임 목록, 채점 횟수와 학습된 값, 점수 그래프, 기록 지우기.
비교 모드에서는 왼쪽이 보간 없는 일반 확대, 오른쪽이 보간 결과다.

## RIFE 생성기

`src/rife.cpp`, `tools/rife_export.py`

- 진짜 프레임 쌍마다 신경망을 별도 스레드에서 한 번 돌려 시점 0.5의 움직임과 마스크를 얻고, 합성은 원본 해상도에서 셰이더로 한다. 입력을 줄여도 화면이 흐려지지 않고, 표시 프레임마다 신경망을 돌리지 않아도 된다.
- 표시 시계를 신경망 시간만큼 더 늦추고, 새 결과가 나올 때까지 앞 프레임 쌍을 계속 보여 준다.
- 실행 파일 옆 `rife` 폴더(약 57MB)의 DLL과 모델을 실행 중에 불러온다. 폴더가 없거나 실패하면 블록 매칭을 쓴다 (폴더 없이 실행해 확인함). git과 공개 릴리스 zip에는 들어가지 않는다.
- 모델은 RIFE v4.26 (Hugging Face `hzwer/RIFE`의 `RIFEv4.26_0921.zip`). `python -I tools/rife_export.py flownet.pkl rife.onnx`로 변환한다.
- 신경망은 Windows의 DirectML로 돌리므로 GPU 제조사에 묶이지 않지만, NVIDIA GTX 1060에서만 확인했다.
